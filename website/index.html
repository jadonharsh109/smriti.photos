संजोई हुई। Every memory, lovingly kept — a photo library that never leaves your machine.

Smriti turns the photo folders already sitting on your Mac or PC into a proper library — यादें, लोग, जगहें — with everything computed on your own machine, and none of it leaving it. No cloud. No account. Your original files are never moved or modified.

Your photos never leave the room

Faces are recognised, places are named and trips are found on your own CPU. Setting up a library downloads the face-recognition models once (about 280 MB) — the only download Smriti ever makes. After that you can pull the network cable out and everything still works.

Every way through your photos

One folder in, and a whole library out — organised the way you would have organised it yourself, if you'd had a spare decade.

Timeline

A date-grouped justified grid, virtualized for six-figure libraries, with a time-proportional year scrubber and a lightbox that zooms on double-click.

People

Face detection and recognition on your CPU — SCRFD and ArcFace via onnxruntime — clustered into people you can name, merge and hide. No face ever touches a server.

Places

GPS read from EXIF and QuickTime, reverse-geocoded offline from a bundled GeoNames dataset, and shown on an interactive globe that fetches no map tiles.

Events

Trips and moments found automatically from the gaps in your timeline, then titled by city and date. Nothing to tag, nothing to file.

Albums

Virtual collections layered over the folders you already have, so your directory structure stays exactly as you arranged it.

Duplicates & cleanup

Exact matches by BLAKE2 and near-duplicates by perceptual hash, with a keeper suggested for you. Cleanup moves files to the system Trash — always recoverable.

Google Takeout repair

Hand it the .zip parts of a Google Photos export and get back a folder of repaired photos, with the dates and GPS Google moved into sidecar files put back where they belong.

Export

Select anything at all — a person, a trip, a day, a search — and save the original files out as a .zip. The originals, not re-encodes.

Locked

A passcode-protected section. Anything you put in it vanishes from every other view — timeline, people, places, search — until you unlock it, and it re-locks itself when you walk away.

Videos

Metadata from ffprobe, poster frames, and smooth scrubbing over HTTP range requests. The desktop app bundles its own ffmpeg — nothing to install.

Drive-aware

External drives are tracked by disk identity, so unplugging and replugging just works. Nothing is ever marked missing while a drive happens to be offline.

Documents & screenshots

Screenshots, scans and receipts are recognised and kept out of your timeline by default — filed in their own place, so the memories stay memories.

Coming from Google Photos

A Takeout export is a pile of numbered zips with the metadata torn out of the photos. Smriti puts it back.

What the repair fixes

  • Dates. Photos that lost their EXIF — Snapchat and WhatsApp images, anything renamed — get their capture time from Google's sidecar, written into the file itself so other apps see it too. A photo that still has its own date is never overwritten.
  • Places. GPS from the sidecar, for the photos that lost it.
  • Albums. Kept as folders, and turned into Smriti albums if you ever add the folder to your library.
  • Duplicates. Takeout stores an album's photos twice, byte for byte. Both paths are recreated, but the second is a hardlink — the mirror is exact and the bytes exist once.

And what it refuses to do

It stops at a folder, on purpose. Repairing an export and deciding to live with those photos are two different decisions, so it makes only the first: you get an ordinary folder you can open in Finder, copy to a drive, or ignore entirely.

Nothing is re-encoded. The capture date is spliced into the JPEG's metadata segment, leaving every byte of image data untouched. Your .zip files are only ever read.

Select every part you downloaded at once — Google routinely files a photo's metadata in a different part from the photo itself, so the parts are paired against each other before anything is unpacked. Smriti says up front what it found, and says so plainly when the set looks incomplete.

Space. The import copies photos out of the archives, so it needs roughly as much free space as the export itself. Smriti checks before it starts, and an interrupted repair picks up where it left off.

Three steps, one evening

Point it at a folder and it does the rest.

Install it

Download for your platform below and open it. Python, ffmpeg and every dependency are already inside the app — there is nothing else to install.

Point it at a folder

Add any folder of photos, on your disk or an external drive. The first one you add downloads the face-recognition models — about 280 MB, once, and the only download Smriti ever makes.

Let it think

It indexes, thumbnails, finds faces, places and trips in the background while you use it. Come back to a library that organised itself.

Or run it headless

For an always-on machine, or to reach your library from other devices on the LAN.

Install

# macOS
brew install jadonharsh109/tap/smriti

# any platform, Python 3.12+ —
# grab the .whl from the latest release
pip install ./smriti_photos-*-py3-none-any.whl
Don't run both. The desktop app and a headless server would write the same database. Pick one.

Use

smriti              # serve at :6969
smriti start        # …or in the background
smriti status       # is it running?
smriti logs -f      # follow the server log
smriti stop         # stop it
smriti models       # face models (~280 MB)

# keep it running at login
brew services start smriti

ffmpeg is optional here and enables video indexing. The desktop app bundles its own.

Where your data lives

One folder, and you can read every part of it.

PathWhat
library.dbSQLite index (WAL)
thumbs/Grid thumbnails, precomputed WebP
previews/1600px lightbox previews, lazy, ~10 GB cap
models/Face-recognition ONNX models
desktop.logServer log — the first place to look

That's ~/.smriti, or ~/Library/Application Support/Smriti for a fresh macOS install and %LOCALAPPDATA%\Smriti on Windows. Override it with SMRITI_DATA_DIR. Deleting the folder fully resets Smriti — your photos are untouched, because they are only ever read.

Read the whole thing

Smriti is open source, and the interesting parts are worth a look: an embedded relocatable CPython inside a Tauri shell, raw ONNX face recognition with no framework underneath it, offline reverse geocoding, and a timeline that stays smooth at six figures.

Building it needs uv, Node 20+ and ffmpeg on PATH — plus Rust 1.85+ for the desktop shell. Every build input is pinned by sha256. 

git clone https://github.com/jadonharsh109/smriti.photos
cd smriti.photos

uv sync                        # backend
(cd frontend && npm install)    # frontend
uv run python scripts/fetch_models.py

./scripts/start.sh             # serve :6969
./scripts/dev.sh               # hot reload
